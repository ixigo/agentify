One-time setup

Install the GitHub workflow

From inside the repo, agentify workflow install detects GitHub from your git remote and lays down the skill bundle. You need the gh CLI installed and signed in first — the workflow checks gh auth status before it touches anything.

# install the gh CLI, then sign in
gh auth login

# from the repo: auto-detects GitHub from the remote
agentify workflow install          # or: agentify workflow install gh
agentify workflow install

What your agent does on its own

Four moves take a shaped issue to a draft PR. You only do the first — opt the issue in. Each move is a skill in the bundle; the agent runs them in order.

01 · Triage

Opt an issue in

github-triage runs the board through a label state machine — needs-triage, needs-info, ready-for-agent, ready-for-human, wontfix, one state label each. Opting in means moving an issue to ready-for-agent; add the agentify-ready label when you want several picked up at once. A rough issue gets shaped first — grill-me asks one question at a time until it is concrete, then files it with gh issue create.

02 · Pick it up

Load the issue as a checklist

gh-autopilot confirms gh auth status, selects the target (an issue number, latest, or first), and turns gh issue view into an execution checklist. All GitHub reads and writes stay here.

03 · Implement

Work in an isolated worktree

worktree-autopilot cuts a fresh branch and git worktree off the right base, makes the smallest change that fixes the issue, and verifies it with the repo's own formatting, linting, type checks, and tests. It commits with a conventional message and leaves your checkout untouched.

04 · Raise it

Open a draft PR

pr-creator re-checks gh and auth, confirms the base and source branch, title, and body, then opens a draft pull request with gh pr create --draft and hands back the link. Nothing is marked ready for review unless you ask.

You never invoke it by name. You don't type skill names or call a command per step. You describe what you want — "triage the board", "pick up #42", "open the PR" — and the matching skill activates from its description. Opt the issue in; the agent takes it from there.

A day with the workflow

A bug lands on the board. You spend a minute on it; the agent spends the rest.

  1. Someone files a vague report. You run a grilling pass until it is concrete, then move it to ready-for-agent.
  2. You say "pick up the ready issue." The agent loads it, branches into a worktree, implements and verifies the fix.
  3. It opens a draft PR and drops the link in the thread. You review, nudge, and mark it ready when you're happy.
What the bundle installs

Seven skills, templated for your provider: github-triage (label state machine), grill-me (shape a new issue, then file it with gh issue create), gh-autopilot (resolve issue/PR context with gh), issue-killer (fan opted-in issues out to parallel tmux worktrees), worktree-autopilot (isolated implement, verify, commit), pr-creator (draft PR with prerequisite checks), and commit-creator (focused, conventional commits).

Run several at once

When more than one issue is opted in, issue-killer launches one tmux pane and one worktree per issue from gh issue list --label agentify-ready, each agent opening its own draft PR. Watch them with tmux attach -t issue-killer. Hand-offs are recorded with agentify ctx note, and every worktree gets its own .agentify/ store, so notes stay per-checkout.

The label state machine
LabelMeans
needs-triageA maintainer still needs to evaluate the issue.
needs-infoWaiting on the reporter for more detail.
ready-for-agentFully specified and agent-suitable — the opt-in state.
ready-for-humanNeeds human implementation.
wontfixWon't be actioned.

Each issue carries one state label and one category label. The agentify-ready label is the fan-out selector for running several in parallel.

Push options and guardrails

Draft by default: nothing is marked ready for review automatically, and non-draft PRs happen only when you ask. No force-push, no rewriting shared history, and nothing is closed or merged on your behalf. Issues are chosen by the opt-in label or explicit numbers — never arbitrary open issues — and every triage comment posted to GitHub carries > This was generated by AI during triage. at the top.

Board queries you can run 
# readiness
gh auth status

# the opted-in board
gh issue list --label agentify-ready --state open --limit 5 --json number,title,url

# load one issue as a checklist
gh issue view <number> --json number,title,body,labels,assignees,url
If something's off

“Unknown command: workflow” — update Agentify with the installer and open a new terminal. No platform detected — the remote isn't GitHub, or there's no origin; pass it explicitly with agentify workflow install gh. gh not found — install the GitHub CLI and run gh auth login, then re-run the install.
