One-time setup

Install the GitLab workflow

From inside the repo, agentify workflow install detects GitLab from your git remote and lays down the skill bundle. You need the glab CLI installed and signed in first — the workflow checks glab auth status and glab repo view before it touches anything.

# install the glab CLI, then sign in
glab auth login

# from the repo: auto-detects GitLab from the remote
agentify workflow install          # or: agentify workflow install glab
agentify workflow install

What your agent does on its own

Four moves take a shaped issue to a draft MR. You only do the first — opt the issue in. Each move is a skill in the bundle; the agent runs them in order.

01 · Triage

Opt an issue in

gitlab-triage manages the board conservatively — it prefers your project's existing labels over inventing new ones and confirms the repo with glab repo view before any change. Opting in means moving an issue to ready-for-agent; add agentify-ready when you want several picked up at once. A rough issue gets shaped first — grill-me asks one question at a time until it is concrete, then files it with glab issue create.

02 · Pick it up

Load the issue as a checklist

glab-autopilot confirms glab auth status and glab repo view, selects the target (an issue number, URL, latest, or first), and turns glab issue view into an execution checklist. All GitLab reads and writes stay here.

03 · Implement

Work in an isolated worktree

worktree-autopilot cuts a fresh branch and git worktree off the right base, makes the smallest change that fixes the issue, and verifies it with the repo's own formatting, linting, type checks, and tests. It commits with a conventional message and leaves your checkout untouched.

04 · Raise it

Open a draft MR

pr-creator re-checks glab and auth, confirms the base and source branch, title, and body, then opens a draft merge request with glab mr create --draft and hands back the link. Nothing is marked ready for review unless you ask.

You never invoke it by name. You don't type skill names or call a command per step. You describe what you want — "triage the board", "pick up that issue", "open the MR" — and the matching skill activates from its description. Opt the issue in; the agent takes it from there.

A day with the workflow

A bug lands on the board. You spend a minute on it; the agent spends the rest.

  1. Someone files a vague report. You run a grilling pass until it is concrete, then move it to ready-for-agent using your project's label.
  2. You say "pick up the ready issue." The agent loads it, branches into a worktree, implements and verifies the fix.
  3. It opens a draft MR and drops the link in the thread. You review, nudge, and mark it ready when you're happy.
What the bundle installs

Seven skills, templated for your provider: gitlab-triage (conservative label/state management), grill-me (shape a new issue, then file it with glab issue create), glab-autopilot (resolve issue/MR context with glab), issue-killer (fan opted-in issues out to parallel tmux worktrees), worktree-autopilot (isolated implement, verify, commit), pr-creator (draft MR with prerequisite checks), and commit-creator (focused, conventional commits).

Run several at once

When more than one issue is opted in, issue-killer launches one tmux pane and one worktree per issue from glab issue list --label agentify-ready, each agent opening its own draft MR. Watch them with tmux attach -t issue-killer. Hand-offs are recorded with agentify ctx note, and every worktree gets its own .agentify/ store, so notes stay per-checkout.

Labels on GitLab

GitLab projects usually carry their own label taxonomy, so the workflow prefers existing labels over creating new ones — if an equivalent is missing it reports it and asks rather than inventing one. The states it maps onto are needs-triage, needs-info, ready-for-agent, ready-for-human, and wontfix, with the agentify-ready label as the fan-out selector for running several in parallel.

Push options and guardrails

Draft by default: nothing is marked ready for review automatically, and non-draft merge requests happen only when you ask. No force-push, no rewriting shared history, and no closing issues or merging MRs on your behalf. Labels are never created without approval, issues are chosen by the opt-in label or explicit numbers, and every triage comment posted to GitLab carries > This was generated by AI during triage. at the top.

Board queries you can run 
# readiness
glab auth status
glab repo view

# the opted-in board
glab issue list --label agentify-ready --output json | head -c 20000

# load one issue as a checklist
glab issue view <number> --output json
If something's off

“Unknown command: workflow” — update Agentify with the installer and open a new terminal. No platform detected — the remote isn't GitLab, or there's no origin; pass it explicitly with agentify workflow install glab. glab not found — install the GitLab CLI and run glab auth login, then re-run the install.
