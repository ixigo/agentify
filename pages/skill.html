The skill command.

Two moves: list shows every built-in skill, and install writes the ones you want onto disk for your agent. Browse them first in the skill catalog.

Guides Switch tools Board to PR Tune it See your usage Skills
List

See what's available

Prints every built-in skill with its supported providers (codex, claude, gemini, opencode), any aliases and a one-line description. Add --json for the full record.

agentify skill list
Install

Put one on disk, or all of them

Pass a skill name or all. Names resolve through aliases, so ado installs ado-autopilot and prints the resolution. Scope defaults to project.

agentify skill install tdd
--provider

Pick the agent

One of codex, claude, gemini, opencode, or all. Leave it off and Agentify uses the defaultProvider from your config. Files land in that provider's folder.

agentify skill install qa --provider claude
--scope

Repo or user

project (the default) writes into the repo, so teammates pick up the same skills. user installs into your per-user skills directory and stays out of source control.

agentify skill install qa --scope user
Skills are opt-in. Nothing is written until you run install. During a session the catalog is matched to your plain requests automatically — installing just makes a skill travel with the repo or your account.

Examples

Every flag below is accepted by skill list and skill install; --json and --root work on both.

# see every built-in skill, its providers and aliases
agentify skill list
# machine-readable output
agentify skill list --json
# install one skill at project scope (the default)
agentify skill install tdd
# choose provider and scope explicitly
agentify skill install pr-creator --provider claude --scope user
# install every built-in for a provider
agentify skill install all --provider codex
# overwrite a skill that is already installed
agentify skill install tdd --force
# preview the writes without touching disk
agentify skill install all --provider codex --dry-run

Edge cases

A skill is already installed

By default an existing skill file is left untouched and reported as skipped. Pass --force to overwrite it with the current built-in version.

Try it without writing

--dry-run resolves the planned provider, scope and target paths and reports them without touching disk — useful as a CI pre-flight before committing a skill set.

Short names and aliases

Many skills carry aliases (for example ado for ado-autopilot, glab-triage for gitlab-triage). Install resolves them and prints Resolved alias <requested> -> <name>. Run agentify skill list to see each skill's aliases.

Where files land

At project scope, skills are written under the repo: .codex/skills, .claude/skills, .gemini/skills or .opencode/skills, depending on the provider. At user scope they go to that provider's per-user skills directory in your home folder.
