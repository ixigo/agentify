Built for subscription plans. Agentify routes work through your Claude Code and Codex subscriptions. The dollar ceilings below are API-equivalent estimates used to rank and cap work, not charges to a card.

The three things most people change

Configuration is deep-merged, so you set one key and leave the rest at their defaults.

models.profile

Pick an objective

cost, balanced (default), or performance. Profiles choose within hard ceilings and local eval evidence. A higher price is never treated as proof of higher quality.

models.budget

Add spend caps

Rolling daily and monthly caps over locally recorded spend. onLimit: block fails before starting another provider process.

models.routes

Override one route

Change a single route's provider, model, or ceiling. The others keep their defaults, and per-route ceilings hold across fallbacks.

A focused config

Chooses the balanced profile, adds rolling caps, keeps deterministic summaries, and leaves pre-push review off until you opt in. model: null lets the provider CLI use its configured default; pin a full model ID only when reproducibility matters more than automatic updates.

models:
  profile: balanced
  budget:
    dailyUsd: 5
    monthlyUsd: 50
    onLimit: block
  routes:
    review:
      provider: codex
      model: null
      maxBudgetUsd: 0.75

context:
  injection: relevant
  sessionSummaries: extractive

hooks:
  prePush: false

Go deeper

Choose models by objective

Profiles select within the same budget and tier bounds. cost picks the cheapest evaluated route that meets the quality floor and will not silently downgrade without evidence. balanced uses the lowest measured cost per passing task, and behaves like the explicit route table when there is no eval evidence. performance escalates only when local evaluations show a gain. For a one-off, --profile, --provider, and --model test a route without changing the repo policy, for example agentify delegate quick "summarize this diff" --provider codex --dry-run.

Override routes in full 
# change only the routes you need; the rest keep defaults
models:
  routes:
    quick:
      provider: claude
      model: haiku
      maxBudgetUsd: 0.10
      maxTurns: 4
      timeoutSeconds: 120
    review:
      provider: codex
      model: null
      maxBudgetUsd: 0.75
      maxTurns: 20
      timeoutSeconds: 600
Opt-in features

These add cost, external tooling, or broader automation, so they stay off until you enable them. Turn one on at a time and verify with agentify models or agentify route explain.

# cross-vendor review before every push (advisory; prints, never blocks)
hooks:
  prePush: true
# then install the managed hook
# run: agentify hooks install

# add providers only after you evaluate them
models:
  providers:
    gemini:
      enabled: true
    opencode:
      enabled: true

# external search toolchain; the built-in index is the default
toolchain:
  zoekt: true
Context behaviour

The default injection: relevant policy is task-scoped and budgeted. Change the token budget only when an eval shows a better number for this repo. Reserves hold token slices for safety-critical classes so bulky items cannot crowd out decisions and unresolved failures.

context:
  injection: relevant
  maxInjectedTokens: 1200
  reserve:
    decisions: 250
    failures: 250
  # extractive (default, no model cost) | llm (budgeted) | off
  sessionSummaries: llm
  summary:
    llmMinEvents: 20
    maxBudgetUsd: 0.03

For the ACP transport, acpInjection and acpCapture are independent and default to off. acpCapture: auto keeps one writer: Codex uses proxy capture while Claude keeps its hooks. Start it with agentify acp --provider codex.

Register the MCP server

MCP registration for Claude Code and Codex is opt-in. Their lifecycle hooks already cover the context tools, so the Agentify MCP server is not registered for them by default. Set install.mcp: true or pass agentify install --mcp to register it anyway. MCP stays fully supported through agentify serve, which is the integration path for MCP-only agents.

Check before it runs

agentify models lists routes, installed provider CLIs, fallback targets, limits, and which ceilings each CLI enforces natively. agentify route explain "design the migration" --profile performance shows the selected profile and model, evidence source, budget, fallback chain, and any alias-drift warning without invoking a provider. agentify delegate review --diff origin/main --dry-run resolves the exact command and sandbox policy while keeping the provider process stopped. agentify doctor checks local toolchain and provider readiness after config changes.
