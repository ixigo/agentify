A session, start to finish.

Hooks in Claude Code and Codex call Agentify at five moments. You don't run anything; it's all in .agentify/ as plain JSONL if you want to look.

The sessions shown are illustrative.

01
Session start

Loads what matters

Notes, decisions and hot files that match the task are injected, chosen within a token budget so a long note never crowds out the task.

## Agentify context (relevant to this task)[decision] ADR-42: fixed 30s retry delay3 of 214 notes · 412 tokens
02
While it works

Tracks edits and commands

Every edit and command is recorded. Files that keep coming up become hot files for next time.

edit src/worker/retry.jsexec npm test (exit 0)tracked · 0 model calls
03
Before a rerun

Flags repeat failures

When the agent is about to run a command that failed before, it sees the earlier error first.

$ npm test -- --runInBand⚠ failed last session · ERR_SOCKET_TIMEOUT
04
Before “done”

Checks its own change

The agent runs risk for the blast radius and test --since for only the affected tests.

$ agentify risk --since main3 files · 2 callers · suggested: test/retry.test.js
05
Session end

Writes a handoff

A short summary built from what was tracked, so the next session starts warm. No model call.

handoff · 6 edits, 1 decision, 1 failure avoidedwritten · 0 model calls
When you want to

Things you can run yourself

Your agent runs most of these. They're here when you want a look or a nudge.

agentify ctx decision "chose X over Y because Z"

Record a decision that should outlive the session.

agentify delegate review --diff main

Get a second opinion from the other vendor.

agentify stats

See how often Agentify ran on this machine and what it did.

Model routing

The right model for each job

agentify install writes a routing table to .agentify.yaml. Your agent hands work out instead of doing everything itself.

KindDefaultUsed for
quickClaude HaikuSmall edits, mechanical changes, quick questions
implementClaude SonnetStandard features and multi-file refactors
heavyClaude FableArchitecture, deep debugging, high-risk changes
reviewCodexAn independent review from the other vendor
researchClaude HaikuExploration, summaries, doc lookups
What if a CLI is missing or logged out?

Each run checks the provider first. If it isn't ready, Agentify falls back to the other vendor at the same capability tier, so a review never silently jumps to a bigger model. Every route has hard limits on turns, time and estimated cost.

Change the routes

Edit models.routes in .agentify.yaml, or see Tune it. agentify models shows the current table and which CLIs are ready.

Beyond Claude Code and Codex

Other agents can use it too

MCP

Any MCP-capable agent

Run agentify serve, or agentify install --mcp to register it. Tools: ctx_load, ctx_note, ctx_match, ctx_decisions, ctx_handoff, query, risk, test_select.

Opt-in

Why MCP is off by default

Hooks already cover Claude Code and Codex, so install doesn't register MCP for them unless you ask. A Codex build without hooks still gets it.

ACP

Full agent sessions

agentify acp --provider codex sits between an ACP client and the agent and forwards messages unchanged. Context injection and capture are opt-in.

Your data

Local, plain, removable

Plain JSONL

Everything lives in .agentify/. Notes and decisions are shared across every worktree of the repo.

No server

No daemon and no account. Agentify itself only goes online for the opt-in version --check; delegated runs use your provider CLIs.

Pause or remove

agentify ctx pause stops tracking; agentify uninstall removes only what Agentify added.
